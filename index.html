Users & Roles

Two roles.

One person photographs the receipt and creates the session. Everyone else joins and claims their items.

Host / Payer
Photographs the receipt
Opens the app, points at the receipt, and captures the image. The photo is sent to Google Cloud Vision for OCR processing.
Reviews extracted items
All items parsed from the receipt are shown before splitting begins. The host can edit names or prices if OCR made a mistake.
Creates session and shares link
A unique session is created in Supabase. The host shares a link or QR code — guests join without needing an account.
Finalizes the split
Once all items are assigned, the host locks the session. Each person's total — including proportional tax — is calculated and displayed.
Guest / Participant
Joins via link or QR code
Opens the shared link on any browser. No account or app install required — the session loads immediately.
Drags items into their basket
Items from the receipt are shown in an unassigned pool. The guest drags each item they ordered into their personal basket.
Marks shared items
If an item was shared with others, the guest can assign it to multiple people. The cost divides evenly among them.
Sees their final amount owed
After the host finalizes, each guest sees their item subtotal plus their proportional share of tax.

Guardrails & Edge Cases

Edge cases
we handled.

Shared Items
Problem: Multiple people share one item.
Solution: Items can be assigned to multiple people — cost splits evenly among them.
Tax Fairness
Problem: Even tax splits are unfair when order sizes vary.
Solution: Tax scales with each person's item subtotal.
Technical Overview

The stack.

System architecture diagram.

Why React Native + Expo?
One codebase for iOS and web. Expo handles native build complexity. Nativewind brings Tailwind to React Native.
Why Supabase over Firebase?
Real Postgres with row-level security and built-in Realtime. No vendor lock-in from Firebase's proprietary data model.
Why a separate Python backend?
Parsing logic is isolated from the app. We can update the parser without touching the frontend.
How it all fits together
App sends image → Cloud Vision returns raw text → Python structures the items → Supabase stores the session → Realtime pushes basket updates to every guest.
Challenges

Challenges.

Real-Time Multi-User Sync
Multiple guests assigning items at the same time creates race conditions. We used Supabase Realtime with optimistic UI updates and server-side conflict resolution to prevent two users from claiming the same item.
Cross-Platform Drag & Drop
Drag-and-drop across iOS and web in React Native required careful use of Gesture Handler and Reanimated. Keeping basket totals updating live at 60 fps took significant tuning.
